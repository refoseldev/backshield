# BackShield для Garry's Mod

BackShield — серверная защитная библиотека для аудита Lua-аддонов и усиления безопасности пользовательских обработчиков `net.Receive`.

## Установка

1. Скопируйте папку `backshield` в `garrysmod/addons/`.
2. Перезапустите сервер.
3. Проверьте сообщения BackShield в серверной консоли.

Результаты также записываются в файл:

```text
garrysmod/data/backshield/events.log
```

По умолчанию BackShield запускается в **режиме аудита**. Библиотека не удаляет файлы, не блокирует игроков и не запрещает динамический Lua-код автоматически.

## Команды

Команды можно выполнить из серверной консоли. В игре они доступны только суперадминистратору.

- `backshield_scan` — повторно просканировать подключённые Lua-файлы.
- `backshield_report` — вывести подробные результаты и список известных сетевых обработчиков.

## Защита сетевого обработчика

Обработчики, принимающие данные от клиента, рекомендуется регистрировать через `BackShield.Receive` вместо обычного `net.Receive`:

```lua
BackShield.Receive("shop.buy", {
    rate = 4,       -- стабильное число сообщений в секунду от игрока
    burst = 8,      -- допустимый кратковременный всплеск
    maxBits = 4096  -- максимальный размер сообщения в битах
}, function(length, ply)
    local itemId = net.ReadUInt(16)
    local item = Shop.Items[itemId]

    if not item then return end
    if not ply:CanAfford(item.price) then return end

    -- Цена, права и состояние должны проверяться на сервере.
    -- Нельзя доверять значениям, которые прислал клиент.
    Shop:Buy(ply, itemId)
end)
```

Для каждого игрока используется алгоритм token bucket. Слишком частые и слишком большие сообщения отклоняются и записываются в журнал. Пользовательский обработчик запускается через `xpcall`, поэтому его ошибка будет зарегистрирована вместе с трассировкой.

## Настройка

Основные параметры находятся в:

```text
lua/backshield/sh_config.lua
```

Пример конфигурации:

```lua
BackShield.Config = {
    ScanOnStartup = true,
    ScanDelay = 3,
    MaxFileBytes = 1024 * 1024,
    ReportThreshold = 5,
    LogToData = true,

    MonitorDynamicCode = true,
    BlockDynamicCode = false
}
```

- `ScanOnStartup` — запускать сканирование после загрузки сервера.
- `ScanDelay` — задержка сканирования в секундах.
- `MaxFileBytes` — максимальный размер проверяемого Lua-файла.
- `ReportThreshold` — минимальный суммарный балл для попадания файла в отчёт.
- `LogToData` — записывать события в каталог `data`.
- `MonitorDynamicCode` — журналировать вызовы `RunString` и `CompileString`.
- `BlockDynamicCode` — блокировать такие вызовы. Включайте только после проверки журнала.

## Исключения

Чтобы исключить из сканирования целую директорию, добавьте её префикс в `IgnoredPathPrefixes`:

```lua
IgnoredPathPrefixes = {
    "backshield/",
    "trusted_addon/"
}
```

Можно скрыть только конкретный тип срабатывания в определённом файле:

```lua
IgnoredFindings = {
    ["my_addon/server/sv_loader.lua"] = {
        "dynamic_code"
    }
}
```

Не добавляйте файл в исключения только потому, что он набрал высокий балл. Сначала проверьте найденные строки и назначение кода.

## Возможные типы срабатываний

- `dynamic_code` — использование `RunString`.
- `dynamic_compile` — использование `CompileString`.
- `remote_code` — возможное выполнение загруженного из сети содержимого.
- `net_dynamic` — возможная передача сетевых данных в динамический Lua-код.
- `sql_concat` — составление SQL-запроса конкатенацией строк.
- `console_command` — выполнение команды серверной консоли.
- `binary_module` — загрузка Lua- или бинарного модуля через `require`.
- `obfuscation` — конструкции, похожие на сокрытие строк через `string.char`.

Баллы являются эвристической оценкой риска, а не доказательством заражения. Некоторые легитимные аддоны используют опасные API по уважительным причинам.

## Режим блокировки динамического кода

Параметр:

```lua
BlockDynamicCode = true
```

блокирует вызовы, проходящие через глобальные функции `RunString` и `CompileString` после загрузки BackShield.

Этот режим может сломать легитимные аддоны. Он также не является абсолютной границей безопасности: код, загруженный раньше BackShield, может сохранить ссылки на оригинальные функции. Перед включением изучите журнал и протестируйте сервер на отдельном стенде.

## Рекомендации по безопасным `net.Receive`

Каждый обработчик клиентского сообщения должен самостоятельно проверять:

- тип и диапазон каждого значения;
- существование сущностей через `IsValid`;
- права и роль игрока;
- принадлежность объекта игроку;
- расстояние до объекта, если действие зависит от позиции;
- допустимость действия в текущем состоянии игры;
- цену, награду и другие важные числа по серверным данным;
- частоту и максимальный размер сообщений.

Нельзя принимать от клиента готовые права, стоимость покупки, количество выдаваемых денег, путь к файлу, имя команды или Lua-код.

## Ограничения

- Библиотека не может автоматически исправить ошибки авторизации внутри произвольных аддонов.
- Она не защищает от скомпрометированного бинарного модуля, панели хостинга или учётной записи сервера.
- Сканер может выдавать ложные срабатывания и не гарантирует обнаружение каждого бэкдора.
- Обработчики существующих аддонов необходимо проверять вручную и по возможности переносить на `BackShield.Receive`.

Регулярно обновляйте сервер и аддоны, ограничивайте доступ к файловой системе и панели управления, а также храните проверенные резервные копии.
